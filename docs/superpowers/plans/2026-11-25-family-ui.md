# 家庭界面实施计划

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** 将用户确认的可交互效果稿落实到微信小程序。
**Architecture:** 两个原生 Tab，共享家庭切换组件；我的页以弹层承载成员、邀请、设置和原有资料编辑。通过现有云函数读取真实数据。
**Tech Stack:** 原生 WXML/WXSS/JavaScript，微信云开发。
**Spec:** 本聊天已确认的 family-preview.html 效果稿（主页、我的、家庭切换）。

## Constraints
- 暖白背景、松绿色、圆角卡片；点菜保持待开放。
- 不使用效果稿中的虚构姓名、人数、邀请码。
- 保留已有权限校验及操作确认。
- 在当前工作区继续已有未提交的 Tab 工作，不提交或覆盖用户改动。

## Review focus
- 已有家庭用户主动创建/加入时不能被自动跳走。
- 家庭切换后个人角色、成员和邀请码必须刷新。
- 最后一个家庭消失时返回引导页。
- 请求失败显示重试，不能展示上一个家庭的管理数据。
- 长家庭名、多成员、弹层内容及原生 Tab 遮挡。
