四、本次优化点（评审重点）

较还原版改动了以下六项，请逐条确认是否采纳；通过后才会落到代码。

① 还原偏差
图标回归真实资源：我的页三项入口由 emoji 换回 assets/ui 下的 members / invite / settings 三张 png（已复制到本目录，预览可见）。
② 还原偏差
家庭切换按钮顺序：改为「＋ 创建家庭」primary 在前、「加入家庭」在后，与组件 wxml 一致。
③ 还原偏差
邀请码默认折叠：显示 ••••••，点「显示」才展开，与 my.js 的 inviteVisible 初值一致。
④ 视觉统一
圆角 24rpx、一级字号 42–44rpx：卡片/摘要收回 24rpx（底部弹层保留 48rpx）；大标题与点菜标题收小 2rpx；🍲 大图换成线条碗，去掉系统 emoji 渲染差异。
⑤ 新增模块
主页「我的家人」卡片：复用现有家庭成员数据（头像 + 人数 + 邀请入口），撑起首屏，无新增虚构业务。需确认：这条要不要一起做——代码里 home.js 目前没拉成员数据，采纳的话要加一次 getFamily 调用。
⑥ 入口收敛
家庭切换统一到「我的」：主页家庭名保留显示但改为只读（去掉下拉箭头、不可点），切换弹层只从我的页家庭摘要进入。代码影响：home.wxml / home.js 删掉 family-switcher 引用与 toggleSwitcher / closeSwitcher / switchFamily 方法；我的页逻辑不变，family-switcher 组件本身不动。

五、菜单图标造型选型（新增评审项 Ⓐ）

诉求是「借鉴 iconfont 里的图标造型」——对，就该这么干：挑选造型，导出成 PNG 直接用，不引入它的字体/CSS 机制。现用三张本就是扁平线性风；下面给出 iconfont 上常见的 12 个同风格造型供挑选。仅设计稿新增候选，代码资源未动。

我的推荐组合（语义最贴合 + 三枚成套统一）：
家庭成员 → C 家庭群组（两人一前一后，比单人更能表达「一家人」）
邀请家人 → A 人＋（最直观，「加个人」= 邀请，与现用一致）
家庭设置 → A 齿轮（iconfont 上设置最通用的造型，辨识度高于滑块）
三款统一规格：线性圆头、2px 描边、松绿 #46765a、72×72 PNG。

现用 vs 候选：现有 members / invite / settings 三张（双人 / 人＋ / 双滑块）本身就是扁平线性风，和 iconfont 同源。候选图标体积更小（1.4–2.4KB），造型选择更多。
落地方式：你从上面挑定每组的字母 → 我把对应造型导出成松绿 72×72 PNG，沿用 members/invite/settings 文件名替换 assets/ui 下三张即可，wxml 的 image 引用一行都不用改。不涉及字体、base64、CSS，零兼容风险。
诚实说明：iconfont 网站需登录且动态渲染，我这边抓不到你账号里的具体收藏；上面 12 款是 iconfont 上最常见的同类造型（开源线性图标，同源），已按项目主色重绘。你若看上 iconfont 里某个具体图标，把链接或截图发我，我照着画成同规格 PNG。
